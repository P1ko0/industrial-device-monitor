# 工业设备监控与控制上位机

使用 C++17 和 Qt Widgets 开发的个人项目。客户端通过文本 TCP 或 Modbus TCP 与模拟设备服务端通信，实现设备状态显示、控制请求、参数管理、故障报警和 SQLite 历史报警存储。

当前使用本地模拟服务端进行联调，尚未接入真实 PLC 或工业设备。主表格中的温度、速度来自客户端模拟器；Modbus 速度、温度使用服务端固定测试值。

## 项目仓库与分工

| 组成 | 职责 | 仓库 |
|---|---|---|
| Qt 客户端 | 输入校验、请求编码、回复解析、连接管理、界面显示、参数配置和报警存储 | [industrial-device-monitor](https://github.com/P1ko0/industrial-device-monitor) |
| 模拟设备服务端 | 请求校验、Device 状态机、参数设置、文本 TCP 和 Modbus TCP 接口 | [device-simulator-server](https://github.com/P1ko0/device-simulator-server) |

两个通信通道连接同一个模拟服务端，共享服务端 Device 状态。客户端通过下拉框选择当前操作使用的协议；收到状态回复时检查当前模式，避免另一通道的回复更新状态界面。

## 已实现功能

- **设备控制**：文本 TCP 模式支持启动、停止、复位、故障模拟及速度设定，服务端校验请求及状态转换。
- **状态显示**：根据服务端回复更新状态标签和表格；文本 TCP 断线时状态显示为 `unknown`，重新连接后查询状态。
- **TCP 消息处理**：使用 UTF-8 文本和换行符作为消息边界，通过接收缓冲区处理分批到达和连续到达的消息。
- **连接管理**：文本 TCP 连接失败或断开后约 3 秒重试，避免重复连接；连接成功后停止相关定时器并查询状态。
- **Modbus 通信**：读取输入寄存器和保持寄存器；向启动线圈写入 1，再读回状态确认设备是否启动。
- **报警管理**：文本 TCP 首次观察到 `error` 状态时记录报警；连续收到相同故障状态不重复添加，恢复非故障状态后允许记录下一次故障。
- **SQLite 持久化**：保存报警时间、设备编号、故障码、描述和确认状态；启动时加载历史报警，按报警 ID 更新确认状态。
- **本地参数**：速度设定范围为 0～3000，温度上限为 1～80 ℃；两项均合法后统一更新，使用 JSON 保存及恢复。
- **模拟数据与日志**：每 500 ms 刷新本地模拟数据；界面显示日志，文件追加保存带时间的操作记录。

## 通信功能与地址

| 通道 | 地址 | 设备编号 |
|---|---|---|
| 文本 TCP | `127.0.0.1:5000` | 1 |
| Modbus TCP | `127.0.0.1:1502` | 1 |

| 操作 | 文本 TCP | Modbus TCP |
|---|---|---|
| 启动 | `START` | 向线圈地址 0 写入 1 |
| 状态查询 | `GET_STATUS` | 读取输入寄存器地址 2 |
| 停止、复位、故障模拟 | `STOP`、`RESET`、`FAULT` | 暂不支持，需切换到文本 TCP |
| 发送速度设定值 | `SET_SPEED` | 暂不支持，需切换到文本 TCP |
| 读取速度、温度测试值 | 未作为本项目此通道的数据采集功能 | 读取输入寄存器地址 0、1 |
| 读取参数测试值 | 未作为本项目此通道的数据采集功能 | 读取保持寄存器地址 0、1 |

“应用参数”用于客户端本地模拟，不向服务端发送参数；“发送速度”用于文本 TCP 服务端速度设定。

### Modbus 寄存器映射

以下均为代码使用的零起始地址。

| 区域 | 地址 | 含义 | 当前行为或测试值 |
|---|---|---|---|
| Coils | 0 | 启动命令 | 写入 1 后尝试启动，处理后清零 |
| Holding Registers | 0 | 速度设定值 | 固定测试值 1800 rpm，尚未与 Device 参数联动 |
| Holding Registers | 1 | 温度上限 | 固定测试值 60 ℃，尚未与 Device 参数联动 |
| Input Registers | 0 | 速度反馈 | 固定测试值 2200 rpm |
| Input Registers | 1 | 温度反馈 | 固定测试值 30 ℃ |
| Input Registers | 2 | 设备状态 | 与 Device 同步：0=idle、1=running、2=stopped、3=error |

启动线圈写入成功只表示通信写入成功，设备是否启动应以读回的状态为准。文本协议改变设备状态后，服务端也同步状态寄存器。

## 开发环境与构建

当前开发环境为 Windows、Qt Creator、Qt **6.11.2**。客户端构建配置要求：

| 项目 | 要求或用途 |
|---|---|
| C++ | C++17 |
| CMake | 3.16 及以上 |
| Qt Widgets | 图形界面 |
| Qt Network | 文本 TCP 通信 |
| Qt SerialBus | Modbus TCP 通信 |
| Qt Sql | SQLite 报警存储，需要可用的 QSQLITE 驱动 |

CMake 文件提供 Qt6 / Qt5 查找分支；本项目当前使用 Qt 6.11.2，其他版本兼容性未单独验证。请选择与已安装 Qt 匹配的编译器和构建套件。

### 构建和启动

1. 下载本仓库及上方链接的模拟设备服务端仓库。
2. 在 Qt Creator 中打开服务端的 `CMakeLists.txt`，选择具备所需模块的构建套件，构建并启动；服务端的具体依赖以其构建配置为准。
3. 确认模拟服务端已启动文本 TCP 和 Modbus TCP 监听。
4. 在 Qt Creator 中打开本仓库的 `CMakeLists.txt`，选择 Qt 6.11.2 对应套件，构建并运行客户端。
5. 使用客户端连接功能连接服务端，确认所选通道的连接状态，再进行控制操作。

默认使用本机地址。若修改为跨机器运行，需要同时调整服务端监听地址、客户端目标地址，并确认对应端口可以连通。

## 演示流程

### 文本 TCP 控制与报警

1. 选择文本 TCP 模式，连接服务端并查询状态。
2. 在 `idle` 状态点击 Start，检查服务端返回和界面状态是否变为 `running`。
3. 点击 Stop 后检查 `stopped`，点击 Reset 后检查 `idle`。
4. 点击 Fault，检查状态变为 `error` 并新增报警；故障状态下启动应被拒绝。
5. 选中报警并确认。确认只更新报警标记，解除设备故障需要 Reset。
6. 关闭并重新启动客户端，检查历史报警及确认状态是否恢复。
7. 关闭并重新启动服务端，检查文本 TCP 离线显示、重连及状态恢复。

### Modbus TCP 启动与读取

1. 先通过文本 TCP 将设备复位到 `idle`。
2. 切换至 Modbus TCP 模式，确认通道已连接并读取状态。
3. 点击 Start，向线圈 0 写入 1，读回输入寄存器 2 检查设备状态。
4. 读取速度、温度及参数测试值，与上方寄存器表核对。
5. 需要停止、复位、故障模拟或发送速度时，切回文本 TCP 模式。

## 数据文件

以下文件位于程序的**运行工作目录**，不一定是源码目录。

| 文件 | 用途 |
|---|---|
| `config.json` | 本地速度设定与温度上限；启动时读取并校验 |

## 当前限制与待验证项

- 尚未接入真实 PLC 或工业设备；模拟数据不代表真实设备测量值。
- 主表格温度、速度来自客户端 Simulator，尚未与服务端速度设定及实际设备状态联动。
- 温度上限支持配置与保存，尚未用于自动触发超温报警。
- Modbus 保持寄存器仍为固定测试值，尚未与 Device 参数联动；当前控制功能仅覆盖启动。
- 尚未实现心跳检测；单次连接持续超过 5 秒时的超时取消与重试分支仍待专门验证。
- 报警时间采用客户端收到状态的时间；当前报警接入文本 TCP 故障状态，故障防重复标记仅在本次运行中有效。
- 模式检查尚未解决快速来回切换时的旧回复识别问题。
- 部分回复处理代码仍有重复，后续需整理封装。
